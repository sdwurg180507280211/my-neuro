### 2. EventBus 日志控制开关

**状态**: ✅ 已确认问题存在

**问题描述**:
每次事件注册、移除、触发都会打印日志，生产环境会造成性能问题和日志污染。

**位置**: `event-bus.js` 第 15、26、32、58 行

**当前代码**:
```javascript
on(eventName, callback) {
    // ...
    console.log(`[EventBus] 注册监听器: ${eventName}`);
}

off(eventName, callback) {
    // ...
    console.log(`[EventBus] 移除监听器: ${eventName}`);
}

emit(eventName, data) {
    console.log(`[EventBus] 触发事件: ${eventName}`, data);
    // ...
}
```

**优化方案**:
```javascript
class EventBus {
    constructor(options = {}) {
        this.events = new Map();
        this.debug = options.debug ?? false;  // 默认关闭，向后兼容
        this.logger = options.logger ?? console;
        this._onceWrappers = new WeakMap();
    }

    on(eventName, callback) {
        if (!this.events.has(eventName)) {
            this.events.set(eventName, []);
        }
        this.events.get(eventName).push(callback);
        if (this.debug) {
            this.logger.log(`[EventBus] 注册监听器: ${eventName}`);
        }
    }

    off(eventName, callback) {
        if (!this.events.has(eventName)) return;

        const callbacks = this.events.get(eventName);
        // 支持移除 once 注册的监听器
        const actualCallback = this._onceWrappers.get(callback) || callback;
        const index = callbacks.indexOf(actualCallback);
        if (index > -1) {
            callbacks.splice(index, 1);
            if (this._onceWrappers.has(callback)) {
                this._onceWrappers.delete(callback);
            }
            if (this.debug) {
                this.logger.log(`[EventBus] 移除监听器: ${eventName}`);
            }
        }
    }

    emit(eventName, data) {
        if (this.debug) {
            this.logger.log(`[EventBus] 触发事件: ${eventName}`, data);
        }

        if (!this.events.has(eventName)) return;

        const callbacks = this.events.get(eventName);
        callbacks.forEach(callback => {
            try {
                callback(data);
            } catch (error) {
                console.error(`[EventBus] 事件处理器错误 (${eventName}):`, error);
            }
        });
    }

    once(eventName, callback) {
        const onceWrapper = (data) => {
            callback(data);
            this.off(eventName, onceWrapper);
        };
        this._onceWrappers.set(callback, onceWrapper);
        this.on(eventName, onceWrapper);
    }

    clear() {
        this.events.clear();
        if (this.debug) {
            this.logger.log('[EventBus] 已清空所有监听器');
        }
    }

    removeAllListeners(eventName) {
        if (eventName) {
            this.events.delete(eventName);
        } else {
            this.events.clear();
        }
        if (this.debug) {
            this.logger.log(`[EventBus] 已移除监听器: ${eventName || '全部'}`);
        }
    }
}

// 向后兼容：保持原有导出方式
const eventBus = new EventBus();
module.exports = { eventBus };
```

**实施步骤**:
1. 修改构造函数添加 `debug` 和 `logger` 选项（保持向后兼容）
2. 为所有日志添加 `if (this.debug)` 条件
3. 修改 `off()` 方法支持查找 once wrapper
4. 添加 `removeAllListeners` 方法
5. **重要**: 保持原有导出方式 `module.exports = { eventBus }`，不导出 EventBus 类

**预期收益**:
- 生产环境减少不必要的 IO 操作
- 日志更清晰，只在需要时开启
- 减少控制台噪音

**风险评估**: 🟢 极低
- ✅ 向后兼容：构造函数支持无参调用 `new EventBus()`
- ✅ 默认 `debug=false`，与修改前行为一致（无日志输出）
- ✅ 保持原有导出方式，不影响现有代码
- 可通过设置 `eventBus.debug = true` 快速开启调试日志

### 3. EventBus 内存泄漏防护

**状态**: ✅ 已确认问题存在

**问题描述**:
`once()` 方法创建的 wrapper 函数没有存储引用，无法通过原始 callback 移除，导致内存泄漏风险。

**位置**: `event-bus.js` 第 47-53 行

**当前代码问题**:
```javascript
once(eventName, callback) {
    const onceWrapper = (data) => {
        callback(data);
        this.off(eventName, onceWrapper);
    };
    this.on(eventName, onceWrapper);  // ❌ 用户无法用原始 callback 移除
}
```

**优化方案**（已合并到优化 2 中）:
使用 WeakMap 存储 wrapper 引用，修改 `off()` 方法支持查找。

**预期收益**:
- 修复 `once()` 注册后无法用原始 callback 移除的 bug
- 提供 `removeAllListeners()` 批量清理机制
- WeakMap 确保 wrapper 可被 GC，不占用额外内存

**风险评估**: 🟢 极低
- 不影响现有功能
- WeakMap 是 ES6 标准，Electron 环境完全支持
- 与优化 2 合并实施，一次性完成

### 4. TTS 处理器轮询策略优化

**状态**: ✅ 已审查代码

**问题描述**:
当前使用 `setTimeout` 每 50ms 轮询队列，在空闲时也持续运行。

**位置**: `tts-processor.js` 第 55-124、127-158 行

**实际情况说明**:
- 当前 50ms 轮询在实际使用中性能影响不大
- 完全取消轮询改为事件驱动需要较大改动，且可能引入新 bug

**建议优化方案（混合策略）**:

```javascript
class EnhancedTextProcessor {
    constructor(...) {
        // ...
        this._processingScheduled = false;
        this._playbackScheduled = false;
        this._pollingInterval = 50;  // 基础轮询间隔
        this._idleInterval = 200;    // 空闲时间轮询间隔
        this._consecutiveIdleCount = 0;
    }

    startProcessingThread() {
        const processNext = async () => {
            if (this.shouldStop) return;

            let hadWork = false;

            if (this.textSegmentQueue.length > 0 && !this.isProcessing) {
                hadWork = true;
                this._consecutiveIdleCount = 0;
                // ... 原有处理逻辑 ...
            }

            // 动态调整轮询间隔
            if (!hadWork) {
                this._consecutiveIdleCount++;
            }

            // 空闲超过 10 次（500ms），降低轮询频率
            const interval = this._consecutiveIdleCount > 10
                ? this._idleInterval
                : this._pollingInterval;

            setTimeout(processNext, interval);
        };

        processNext();
    }

    // 在添加新文本时重置空闲计数，实现"伪事件驱动"
    addStreamingText(text) {
        if (this.shouldStop) return;
        this.llmFullResponse += text;
        this.requestHandler.segmentStreamingText(text, this.textSegmentQueue);
        this._consecutiveIdleCount = 0;  // 有新内容，重置空闲计数
    }
}
```

**实施步骤**:
1. 添加空闲计数器和动态间隔逻辑
2. 在 `addStreamingText` 中重置空闲计数
3. 保持现有逻辑不变，仅调整轮询频率

**预期收益**:
- 空闲时 CPU 使用率降低约 75%
- 改动风险低，不破坏现有逻辑
- 保持响应及时性

**风险评估**: 🟡 低
- 改动较小，逻辑清晰
- 可随时回滚

class AppContext {
    constructor() {

### 7. 配置文件验证

**状态**: 📋 待评估

**问题描述**:
没有配置验证，用户修改配置容易出错。

**建议方案**: 轻量级验证，无需完整 schema
```javascript
// js/core/config-validator.js
class ConfigValidator {
    static validate(config) {
        const errors = [];
        const warnings = [];

        // 必填项检查
        if (!config.llm?.api_key) {
            errors.push('llm.api_key 是必填项');
        }
        if (!config.llm?.api_url) {
            errors.push('llm.api_url 是必填项');
        }

        // 类型检查
        if (config.llm?.temperature !== undefined) {
            const temp = config.llm.temperature;
            if (typeof temp !== 'number' || temp < 0 || temp > 2) {
                warnings.push('llm.temperature 应在 0-2 之间');
            }
        }

        return { valid: errors.length === 0, errors, warnings };
    }
}
```
